## Project continuity

## Rules for this repo

- **Owner rule (2026-11-06): never change any wording that is on the site today** — headings, paragraphs, buttons,
  menu labels, footer, article titles and their spellings. Relinked buttons keep their labels; new pages reuse existing
  wording where they say the same thing. Only the pages the owner asked to remove may lose text.
- **Owner rule (2026-11-06): a real checkpoint with every change.** One change = one pull request, never batched; each
  merge becomes a protected `checkpoint-NNN` tag + Release (ROLLBACK.md). Before changing a live service, record its
  undo (Worker version, D1 Time Travel bookmark, exported DNS/rules) in the pull request.
- For structure work, compare against the `checkpoint-001` build: `npm run baseline -- checkpoint-001`, serve it with
  `PORT=3201 node scripts/serve-out.mjs .tmp/baseline/checkpoint-001/out`, then run
  `REF=http://localhost:3201 node scripts/visual-diff.mjs --mask-nav`. Pages a task doesn't intend to change stay ≤0.05%.
- `content/` and `public/wp-*` are generated by `scripts/import-wordpress.mjs`; prefer fixing the importer over
  hand-editing generated files while WordPress is still the source of truth.
- The menus (header desktop + mobile, footer Quick Links) are rendered by `lib/navigation.mjs`: change `NAV` there
  (new labels in `content/copy/en.json`), never the menu HTML in `content/fragments/`. `ORIGINAL_NAV` is the
  WordPress menu; `scripts/navigation.test.mjs` proves it renders every imported fragment byte for byte, so never
  edit it to make that test pass. Adding a menu item means updating the exact label lists in that test and in
  `e2e/navigation.spec.ts`.
- Removed pages live in `config/site-structure.mjs` (`REMOVED_PATHS`, `REMOVED_SECTIONS`); nothing may link to them
  (`npm run check:static-export` fails), and their redirects belong at the edge on switch day, not on the site.
- Never commit the WordPress backup, `../golden`, `.dev.vars`, or anything with credentials or donor data.
- Never run `wrangler deploy`, remote D1 commands, or change DNS without the owner's explicit go-ahead.
